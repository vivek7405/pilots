# Workspace rules for agents that read `.agents/rules/`

Some agents (Antigravity among them) load every markdown file under
`.agents/rules/` and nothing else. This file exists for those.

**`AGENTS.md` at the repo root is the full contract and this does not replace
it. `ARCHITECTURE.md` is the design and is required reading before writing any
code.** What follows is the subset that is expensive to violate, so that an
agent which never opens either file still cannot do the damage.

## Architecture invariants (violating these corrupts state silently)

- **Single-writer.** A host writes ONLY rows describing its own machines.
  The exceptions are narrow and listed in `AGENTS.md`. This does not error
  when broken; it corrupts state through CRDT merges.
- **The data plane never depends on the control plane.** Routing and wake read
  local state only.
- **S3 is the only truth for machine state.** Local NVMe is a cache. The test
  is: wipe any host's disk and nothing is lost.
- **URLs are permanent.** A machine's URL survives suspend, wake, checkpoint,
  restore, promote, redeploy and host migration. Anything that can mint a new
  URL for an existing machine is a bug.
- **Snapshots are host-agnostic**, within a CPU-vendor pool. Nothing
  host-specific may enter a snapshot.
- **Never `ALTER TABLE` a live Corrosion table, and never add a column to one
  that has rows.** cr-sqlite backfills every existing row and gossips the
  backfill; that took Fly's fleet down twice for about 11.5 hours. A shape
  change is a new table plus a dual read.

## Workflow

- **One task per git worktree, always.** `git worktree add -b feat/<slug> ../pilots-<slug> main`.
  Two agents in one checkout collide: a `git checkout` in one moves `HEAD`
  under the other, so the next commit lands on the wrong branch.
- **Never commit on `main`.** Feature branch and a PR, always. Never push to
  `main`, and never merge without explicit per-PR approval.
- **Commit per logical unit and push after each.** Do not batch unrelated work.
- **Imperative commit subjects under 72 chars.** The body explains why, not
  what; the diff shows what.
- **No AI attribution** in commits: no `Co-Authored-By`, no "Generated by".

## Before committing

From `apps/hostd/`, and again from `sdks/go/` and `apps/pilot/`:
`gofmt -l .` must print nothing, then `go vet ./...` and `go test ./...`.
From the root, `npm test`. Run `bash -n` on every shell script you edited and
`node --check scripts/e2e.mjs` — a syntax error in either surfaces only on a
host, mid-bootstrap.

## Testing

`scripts/e2e.mjs` (public API only) and `scripts/cluster/gate.sh` (needs a host
shell) are both **monotonically growing**. Later work adds assertions and never
retires one. Which file a new test belongs in is decided by what can observe
it, and the table is in `AGENTS.md`.

A block that cannot set itself up must fail loudly. A quiet early return
retires every assertion below it at runtime, which is worse than a red test.

**Budget the batteries.** The e2e takes ~35 minutes in full and the gate two
to three hours; neither may be overlapped with the other. Say the ETA before
starting one and run it in the background. Confirm a single fix with
`PILOTS_E2E_ONLY=<sections>` (minutes; the summary names every section not
run and exits 2), and run the full battery once per wave of fixes, never once
per fix. A battery failure is diagnosed by reproducing its calls by hand,
not by re-running the battery. Before a timing run: disk under 85%, no
leftover battery machines, and A/B the previous binary on the same host
before reading code. The full rules are in `AGENTS.md` under "Budget the
batteries before starting them".

## Working on the engine

The uffd handler and the NBD handler are **ports, not rewrites**: they encode
kernel ABI details that are expensive to rediscover. For everything else in
the engine, read the prior-art notes in `docs/prior-art/` before guessing.
Take mechanics, never architecture.
