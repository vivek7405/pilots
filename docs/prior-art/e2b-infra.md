# e2b-infra — architecture notes
_Research date: 2026-09-03, against the local clone at commit e187eb47 (2026-09-02). Paths relative to repo root; orch/ = packages/orchestrator. "(inferred)" marks conclusions not stated in code/comments._

## One-paragraph summary

e2b-infra is a three-tier product: a central REST **API** (Gin, Postgres for durable rows, Redis for the *running* set and the sandbox→node routing catalog) that decides *where* a sandbox runs; a per-node **orchestrator** (one Go binary, root, gRPC :5008 + reverse proxy :5007) that owns *how* it runs — Firecracker in a per-slot netns, guest memory served lazily by an in-process userfaultfd handler over a chained "memfile" diff format, rootfs served as a CoW overlay through an in-process NBD server; and **envd**, a Connect-RPC agent inside every guest. "Create" is a **restore of a pre-booted template snapshot** (memfile + rootfs.ext4 + snapfile + metadata.json + `.header` sidecars, all keyed by build id in GCS/S3), never a cold boot; pause produces a *new build* whose memfile/rootfs are diffs parenting the template, so templates and snapshots share one artifact shape and one chain-resolving header. The whole thing is deployed by Terraform onto Nomad+Consul with an autoscaled sandbox node pool. Everything below the gRPC boundary (uffd, block layout, NBD, netns/slot addressing, provision.sh, pre-pause hygiene, fs-only snapshots) is directly reusable mechanics; everything above it (API placement, Redis catalog, Nomad discovery, LaunchDarkly gating) is exactly the central control plane pilots exists to replace.

## Central control plane — what pilots replaces (explicit list)

Every item below requires a specific machine or managed service to be alive on the request path. pilots' rule 1 forbids all of them.

1. **API tier as the only lifecycle entry point.** `POST /sandboxes` → API → gRPC `SandboxService.Create` (`docs/ARCHITECTURE.md:296-325`). The orchestrator cannot create a sandbox on its own initiative; it does not even know the team.
2. **Placement decided centrally.** Best-of-K over the API's in-memory node map: sample K=3, score `(cpuRequested + reserved + 0.5*usage)/(R=4 * cpuCount)`, take the min (`packages/api/internal/orchestrator/placement/placement_best_of_K.go:23-29, 32-59, 87-124`). Resume prefers the origin node, vetted for CPU/feature compatibility (`placement/placement.go:66-73`; `create_instance.go:373-388`). Origin can be remapped after a placement timeout (`create_instance.go:530-560`, flag `resume-origin-node-remap`).
3. **Node discovery via Nomad** (or Kubernetes/static): `api/internal/orchestrator/client.go:126-148` lists nodes, `:154-206` on-demand connect (documents a 0–20 s discovery gap), `:209-234` dials every ready Nomad node. Node health is the API's local view of the gRPC channel (`nodemanager/status.go:35-58`), with retries then `markUnhealthyLocal` (`nodemanager/sync.go:99-104`).
4. **Redis as source of truth for running sandboxes + routing catalog.** `lifecycle.go:15-46` writes `SandboxInfo{OrchestratorIP, ExecutionID, StartedAt, MaxLengthInHours}` with TTL = max length (`shared/pkg/sandbox-catalog/catalog_redis.go:84-104`). client-proxy reads it per request (`client-proxy/internal/proxy/proxy.go:75-95`).
5. **Postgres for snapshots.** Pause first upserts a `snapshots` row + `env_builds` build row (`api/internal/orchestrator/pause_instance.go:32-40, 121-150`), *then* calls the node; the build row is marked failed/success afterwards (:58-73).
6. **Timeouts and auto-pause enforced by the API evictor**, polling Redis every 50 ms for expired sandboxes (`evictor/evict.go:24-28, 92-141`) and issuing kill or pause (`:144-171`). Keep-alive updates the Redis row then calls the node (`keep_alive.go:19-63`).
7. **Auto-resume on traffic goes through the API**: client-proxy → API gRPC `ResumeSandbox` (`client-proxy/main.go:157-186`; `api/internal/orchestrator/autoresume.go:20-131` waits out pausing/snapshotting transitions, max 3 retries).
8. **LaunchDarkly** gates nearly every engine behaviour at runtime (`shared/pkg/featureflags/flags.go:127-1274` — 60+ flags: `use-memfd`, `use-sync-wp`, `in-place-checkpoint`, `defer-memory-export`, `defer-rootfs-export`, `memfile-diff-dedup`, `resume-prefetch-source`, `guest-pause-reclaim`, `fs-only-resume-api`, `preboot-fs-recovery`, `envd-upgrade-target` …). Each is read per sandbox with an LD context (`orch/pkg/sandbox/sandbox.go:262-271`).
9. **Nomad/Consul servers** schedule the orchestrator as a system job and provide `*.service.consul` DNS (`docs/ARCHITECTURE.md:510-513`).
10. **Template builds routed by the API to a build pool** (`TemplateCreate` gRPC, `docs/ARCHITECTURE.md:462-472`) and marked ready in Postgres.

What is *not* central and therefore directly comparable to pilots: the orchestrator's own `sandbox.Map` (`orch/pkg/sandbox/map.go`), the proxy's per-node routing (`orch/pkg/proxy/proxy.go:66-155`), the template cache, the network slot pool, and all storage reads — none of these consult the API.

## 2. Sandbox lifecycle in the orchestrator (`orch/pkg/sandbox/`)

### Identity and addressing
- `RuntimeMetadata{TemplateID, SandboxID, ExecutionID, TeamID, BuildID, SandboxType}` (`sandbox.go:246-256`). `ExecutionID` is stable across checkpoints and shared with the API; `LifecycleID` is a fresh UUID per Firecracker process and keys proxy connection pools and map-eviction guards (`sandbox.go:321-327`; proxy uses it as `ConnectionKey` at `orch/pkg/proxy/proxy.go:141-143` — "we are not using sandbox id to prevent removing connections based on sandbox id (pause/resume race condition)").
- A sandbox is addressed on the host by its **network slot**: slot index N → netns `ns-N` (`network/slot.go:199`), host-side IP `10.11.0.N/32` from `SANDBOXES_HOST_NETWORK_CIDR` (`slot.go:29,493`), veth pair `veth-N`/`eth0` in `10.12.0.0/16` /31 blocks (`slot.go:30,159,171`), tap `tap0` = `169.254.0.22/30` with fixed MACs (`slot.go:37-40`), guest always `169.254.0.21` (`slot.go:195`). Slot count = `/16 / 2 - 2` ≈ 32766 (`slot.go:529-541`). The orchestrator reaches envd at `http://10.11.0.N:49983` (`health.go:20`, `envd.go:481`).
- Per-sandbox files: `SandboxFiles` from the template's `CachePaths` (`shared/pkg/storage/sandbox.go:28-68`): rootfs `.cow` cache, FC socket, uffd socket, metrics FIFO, cgroup name. Reclaimed at startup by glob (`sandbox.go:78-119` in shared/storage).

### Config knobs that reach FC
`Config` (`sandbox.go:108-142`): `Vcpu`, `RamMB`, `HugePages`, `FreePageReporting`, `FreePageHinting`, `Envd{Version, AccessToken, Vars}`, `FirecrackerConfig{KernelVersion, FirecrackerVersion}`, `VolumeMounts`, `MaxSandboxLengthHours`, `Network` (egress/ingress, mutex-guarded). The gRPC `Create` copies these from `SandboxCreateRequest` (`orch/pkg/server/sandboxes.go:251-272`) and resolves the FC version through a flag (`:245`).

### The gRPC `Create` handler (`orch/pkg/server/sandboxes.go:122-422`)
1. Start-permit semaphore sized by flag `MaxStartingInstancesPerNode` → `ResourceExhausted` "too many sandboxes starting" (`:225-228`).
2. `templateCache.GetTemplate(buildID, isSnapshot, isBuilding, opts)` (`:231-236`) — lazy: returns immediately, fetches headers/files in the background (`orch/pkg/sandbox/template/storage_template.go:81-`).
3. Reads `metadata.json`; `fsOnly = meta.IsFilesystemOnly()`, `filesystemBooted = filesystemBoot(meta, req)` (`:289-290`, `:94-101`).
4. **Branch**: `RebootSandbox` (cold boot, fs-only snapshot or explicit `filesystem_boot`) at `:293-305`, else `ResumeSandbox` at `:307-317`. **Both `POST /sandboxes` (create) and `/resume` map to this one RPC**; `req.Sandbox.Snapshot=true` distinguishes resume (`:349`). A fresh create is a resume of the template's base snapshot — there is no boot path for creates (`docs/ARCHITECTURE.md:322-325`).
5. Missing objects → `FailedPrecondition "sandbox files not found"` so the API can retry after the async upload lands (`:320-325`).
6. `setupSandboxLifecycle` (`:342`, body `:1548-1582`): a goroutine waits on `sbx.Wait`, records execution duration, `Close`s, removes the proxy pool entry.
7. Optional live envd upgrade on resume (`:349-362`), then `markSandboxLive` = `MarkRunning` + start health checks (`:368`, `:1542-1546`). Routing is deferred until here so the sandbox is never reachable during the upgrade's pre-init auth window.
8. Response carries `SchedulingMetadata` (build-id chain + bytes per artifact, `orch/pkg/scheduling/metadata.go:16-49`) and the resolved FC version, "frozen for its lifetime" (`:405-416`).

### `Factory.CreateSandbox` — cold boot (`sandbox.go:642-896`), used only by template builds and fs-only reboots
- Network slot promise (`:679`, `getNetworkSlot :3653-3681`), rootfs provider: **NBD overlay** when `rootfsCachePath == ""` else **DirectProvider** (mmap of a file; template build) (`:691-705`).
- Memory backend is `uffd.NewNoopMemory(size, pageSize)` — FC owns anonymous RAM (`:780`).
- Optional `preBootFn(ctx, rootfsPath)` runs against the NBD device *before* FC starts (`:742`) — this is where e2fsck journal replay and the offline envd swap hook in.
- cgroup created and passed as fd for `CLONE_INTO_CGROUP` (`:747`; `fc/process.go:261-267`).
- `fc.NewProcess` builds a `unshare -m bash -c` start script that mounts a private tmpfs at `/fc-vm/<sbx>` and symlinks kernel + rootfs into it, then `ip netns exec ns-N firecracker --api-sock …` (`fc/script_builder.go:54-63`, `fc/process.go:206`). Rootfs is symlinked to `/dev/null` first, then to the real device once the provider is ready (`fc/process.go:333, 411`) — so FC's fixed drive path is constant across hosts (`fc.ConstantRootfsPaths`, `fc/config.go:64-71`).
- `fcHandle.Create` (`:844`) drives the FC API in order: metrics FIFO → boot source (kernel args below) → drive (`rootfs`, optional io engine + rate limiter) → net iface (`eth0`, `tap0`, fixed MAC, tx rate limiter) → machine config (vcpu, mem, SMT on x86, `TrackDirtyPages=false`, `HugePages=2M` if requested) → entropy device → optional balloon (FPR/FPH) → MMDS metadata → `InstanceStart` (`fc/process.go:329-479`; `fc/client.go:367-402`).
- Kernel cmdline (`fc/kernel_args.go:89-149`): `quiet loglevel=1 init=<init> ip=169.254.0.21::169.254.0.22:255.255.255.252:instance:eth0:off:<dns> ipv6.disable=0 ipv6.autoconf=1 panic=1 reboot=k pci=off i8042.nokbd i8042.noaux random.trust_cpu=on rootflags=discard`, `clocksource=kvm-clock` when envd ≥ 0.2.11 (`reboot.go:39`). `rootflags=discard` is load-bearing: "ext4 issues TRIM on freed blocks so they are elided from the snapshot diff. It must never include noload: a filesystem-only snapshot resume cold-boots … and relies on ext4 replaying the journal on mount" (`fc/process.go:81-86`). Reserved keys an operator overlay may not touch: `init clocksource root ip console rootflags panic reboot loglevel quiet` (`:23-34`).

### `Factory.ResumeSandbox` — the hot path (`sandbox.go:970-1494`)
All resources are started as promises and joined:
1. `uffdPromise` → `uffd.New(memfile, socketPath, logger)` (`:1021-1031`).
2. Prefetch goroutine (`:1054-1146`): source chosen by flag `resume-prefetch-source` ∈ {off, init, last-cycle, both} (`resume_prefetch.go:26-37`). Init trace (build-time working set, `meta.Prefetch.Memory`) is **prefaulted**; last-cycle diff (derived from the memfile header, `buildDiffMemoryPrefetchMapping :61-144`) is **fetch-only** (`p.Prefault = false`, `:1137`) because "prefaulting a multi-GiB diff would load UFFDIO_COPY onto the resume-critical path". The prefetch ctx is cancelled as a *priority* cleanup so teardown aborts a multi-GiB drain first (`:1045-1051`).
3. `overlayPromise` → `rootfs.NewNBDProvider` + `overlay.Start` (`:1149-1181`).
4. `memoryPromise` → `serveMemory` = listen on the uffd unix socket, chmod 777, spawn the serve goroutine (`:1183-1200`; `uffd.go:106-144`).
5. Optional `ips.DenyEgress` before FC resume for throwaway (harvest) resumes (`:1216`).
6. cgroup, `fc.NewProcess` with `RootfsPaths{TemplateVersion, TemplateID, BuildID: rootfs.Header().Metadata.BaseBuildId}` (`:1245-1268`) — "The versions need to be exactly the same as the paused sandbox template because of the FC compatibility."
7. `useMemfd = FCSupportsMemfd(ver) && flag use-memfd` (default true), `useSyncWP = flag use-sync-wp` (default false) (`:1334-1342`); `fcUffd.SetSyncWP` (`:1359`). Comment at `:1336-1341`: FC's `MemBackendConfig` is `deny_unknown_fields`, so an unsupported field "fails the snapshot load loudly instead of silently downgrading".
8. `AssignNetwork` + `runNetworkAssignHook` **before** `fcHandle.Resume` so tcpfirewall lookups by source IP work from the first packet (`:1370-1387`).
9. `fcHandle.Resume` (`:1412`; `fc/process.go:499-663`): in parallel — start FC and wait for its API socket, wait for the uffd socket, symlink rootfs — then `PUT /snapshot/load {snapshot_path, mem_backend:{backend_type: Uffd, backend_path, use_memfd?, use_sync_wp?}, enable_diff_snapshots:false, resume_vm:false}` (`fc/client.go:42-98`), wait for `uffdReady` (FC has connected and sent region mappings + fds), re-apply tx/drive rate limits ("any limits persisted in the snapshot are overwritten"), `PATCH /vm resume`, then `PUT /mmds` with `{instanceID, envID, address: http://192.0.2.1/logs, accessTokenHash}` (`fc/mmds.go:5-12`; `process.go:626-648`).
10. `WaitForEnvd(StartTypeResume, timeout)` (`:1450`; `:3713-3799`): `POST /init` with infinite retries until the flag-driven timeout, cancelled early if FC exits. On the first successful init it records `envd.init.duration`, `uffd.startup.{pages,source_pages,bytes}` (the demand-fault working set needed to reach envd-ready, `:3745-3768`) and `SetStartedAt`.
11. `MarkRunning`, start `Checks` (GET /health every 20 s with a 100 ms timeout, `checks.go:20-23`), spawn the exit-wait goroutine that stops the sandbox when *either* uffd or FC exits (`:1465-1492`).

### Stop / delete / crash
- `Stop` → `fc.Process.Stop`: SIGTERM, 10 s, SIGKILL, 1 s (`fc/process.go:665-730`); descendants are killed via the cgroup, not a pgid. Cleanup is LIFO with priority handlers (`cleanup.go`), returning the slot asynchronously after `ReturnDelay = 3s` to let in-flight proxy requests drain (`network/pool.go:29-31`; `sandbox.go:3670-3676`).
- Stop reasons are a closed set `killed|paused|checkpointing|crashed`; "crashed is the absence of a recorded reason" (`sandbox.go:213-225`).
- Startup reclaim on orchestrator restart: kill orphaned FC process groups found in `/proc` (`orch/pkg/startupreclaim/firecracker.go:21-52`), tear down leaked netns anchors (`network/reclaim.go:9-42`), delete sandbox cache files by glob. **There is no re-adoption of running VMs after an orchestrator crash** — they are killed (inferred from the reclaim code; no adoption path exists).

### Timeouts / auto-pause
Owned by the API (see central list). The orchestrator only stores `endAt` (`Metadata.SetEndAt`, `sandbox.go:310-315`) and updates it on `Update` RPC; nothing on the node reaps on its own timer (inferred: no ticker reads `endAt` in `orch/pkg/server`).

## 3. Memory: uffd + block layout

### Artifact/header format (`packages/shared/pkg/storage/header/`)
- Constants: `PageSize = 4 KiB`, `HugepageSize = 2 MiB`, `RootfsBlockSize = 4 KiB` (`diff.go:10-12`). `IsZero` samples first/middle/last byte then `bytes.Equal(b[:n-1], b[1:])` (`diff.go:24-38`).
- `Metadata{Version, BlockSize, Size, Generation, BuildId, BaseBuildId}` (`metadata.go:32-40`), serialized little-endian at the head of every `.header`. `NextGeneration` bumps `Generation` and keeps `BaseBuildId` (`:53-62`) — Generation = pause/resume cycle count, used to bucket fault-latency metrics by chain depth (`uffd/uffd.go:197-201`; `userfaultfd.go:158-160`).
- `Header{Metadata, Builds map[uuid]BuildData{Size, Checksum, FrameData}, Mapping (compact ~14 B/entry), IncompletePendingUpload}` (`header.go:15-43`). A header is the **complete source map of a virtual file**: every byte range → `(BuildId, BuildStorageOffset)` (`mapping.go:13-20`). `BuildId == uuid.Nil` means "zeros, never read from storage" (`mapping.go:245-262`).
- Diff creation: `DiffMetadata{Dirty, Empty roaring bitmaps, BlockSize}` (`metadata.go:80-84`) → `CreateMapping` packs dirty ranges **contiguously in ascending order** into the new build's data file (`mapping.go:22-45`), empty ranges map to `uuid.Nil`; `MergeMappings(base, diff)` overlays (`:78-243`, a 6-case interval merge); `NormalizeMappings` coalesces adjacent same-build runs only when storage-contiguous (`:245-`). `ToDiffHeader` = merge + normalize + `NextGeneration` + validate at PageSize (`metadata.go:159-222`). Header versions: V3 uncompressed, V4 = `[Metadata][flags][u32 lz4 len][LZ4(Builds + 40-byte mappings)]` (`serialization_v4.go:59`), V5 = same framing with columnar varint mappings + build-id table because "page-granular memfile dedup … can hold millions of entries, blowing past the 64 MiB uncompressed cap" (`serialization_v5.go:13-30`). Uncompressed cap raised to 256 MiB (`serialization_v4.go:23-30`).
- Storage layout per build: `{buildID}/memfile`, `rootfs.ext4`, `snapfile`, `metadata.json`, `memfile.header`, `rootfs.ext4.header`, optional `.zstd`/`.lz4` variants (`paths.go:8-60`). Data files are range-read in `MemoryChunkSize = 4 MiB` chunks (`storage.go:41-42`) or, when compressed, per 2 MiB frame via a `FrameTable` (`compress_config.go:4-16` — "MUST be multiple of every block/page size"). Headerless "old" builds fall back to whole-file mapping (`template/storage.go:60-`).
- Reads through a chain: `build.File.ReadAt` resolves offset → `GetShiftedMapping` (`header.go:148-175`) → that build's `DiffStore` entry (local `.cow`/diff file, chunker over object storage, NFS cache, or a peer) (`orch/pkg/sandbox/build/build.go:52-`, `storage_diff.go`). The chunker caches 4 MiB fetches into a sparse mmap'd local file (`block/streaming_chunk.go:26-58`, `defaultFetchTimeout = 60s :21-24`).

### The uffd handler (`orch/pkg/sandbox/uffd/`)
Handshake (`uffd.go:145-250`): listen on a unix socket; FC connects and sends a JSON array of `Region{base_host_virt_addr, size, offset, page_size_kib}` plus 1 or 2 fds via SCM_RIGHTS (`:160-161`: "1 fd (UFFD) or 2 (UFFD + memfd, on newer versions)"). **Wire gotcha** (`memory/region.go:12-13`): the field is named `page_size_kib` but "is actually in bytes in the deprecated version." Page size is taken from region 0; **all regions must agree and be 4 KiB or 2 MiB** (`userfaultfd.go:231-243`). Buffer for the mapping JSON is 1024 bytes (`uffd.go:36`).

Serve loop (`userfaultfd.go:340-706`): `poll()` on {uffd, exit-fd, self-wake pipe}; `read()` drains `uffd_msg`s (`:294-338`), rejecting `MINOR` events (`:520-522`). Two worker pools: MISSING faults on `wg` (limit 4096, `:33`) and WP faults on `wgWP` (limit 256, `:35-40`) — separated because "the shared pool's MISSING workers can hold a slot through seconds of source-read backoff" (`:130-134`). Locking: `settleRequests` RWMutex guards the page tracker (workers RLock across lookup→install→record; the REMOVE batch takes Lock, `:107-114`); `readSerial` keeps the kernel queue drainable so a blocked madvise can never deadlock an in-flight copy (`:116-121`, test `TestNoMadviseDeadlockWithInflightCopy`).

Per-page state machine (`block/tracker.go:11-38`): `NotPresent → {Clean (read install, WP-armed, content == source), Zero (installed zero page), Dirty (write install or promoted)}`, `Removed` (REMOVE/madvise zapped, absent, reads back as zeros). Export = dirty bitmap + empty (zero ∪ removed); Clean pages are excluded so "a snapshot diff can inherit the page from the parent layer" (`:28-33`, `userfaultfd.go:279-292`).

`faultPage` (`userfaultfd.go:932-1091`) — the ioctl sequence and its gotchas:
- Read faults use `UFFDIO_COPY_MODE_WP` (install + write-protect atomically); write faults mode 0 (`:955-958`).
- Zero pages: for a **4 KiB write fault** `UFFDIO_ZEROPAGE` (`:962-966`); otherwise **`UFFDIO_COPY` from a static 2 MiB zero buffer** (`:967-976`) because "the previous 4K sequence — ZEROPAGE(DONTWAKE) → WRITEPROTECT → wake — had two windows that lose guest writes under the tracker dirty source" and hugetlb has no ZEROPAGE anyway. `header.EmptyHugePage` is the shared buffer (`diff.go:17`).
- Data pages: 2 MiB reads use a `sync.Pool` of scratch buffers, 4 KiB allocate per fault (`:89-97`, `:978-985`); `source.ReadAt` retried 3× with 50→500 ms jittered backoff **while holding `settleRequests.RLock`** (`:987-1031`, noted trade-off). Read failure signals `fdExit` and returns `faultDiscarded` (`:1033-1048`).
- `UFFDIO_COPY` errno handling (`:1052-1090`; `fd.go:132-166`): `EEXIST` → wake, already present; `ESRCH` → process gone, discard; `EAGAIN` or a **short copy** (`classifyCopyResult`, hugetlb can be preempted mid-page) → push onto a deferred queue and write the self-wake pipe, because "the kernel does not auto-redeliver" (`:1070-1079`, `:136-139`). Data is pinned with `runtime.Pinner` for the ioctl (`fd.go:138-140`).
- Features requested: `UFFD_FEATURE_MISSING_HUGETLBFS`, `EVENT_REMOVE`, `WP_ASYNC` (`fd.go:71-73`).
- REMOVE events (`:459-497`) mark pages `Removed`; a REMOVE overlapping an uncaptured CoW-window page cancels the export ("corruption tripwire", `:480-494`).
- Sync-WP faults (`:532-569`, `resolveWriteProtect :735-897`): only delivered by their **forked FC** registered without `WP_ASYNC`; clears protection (`UFFDIO_WRITEPROTECT mode 0` also wakes, `fd.go:180-200`), promotes the page to Dirty, optionally copies the pre-image into a CoW window first (`:809-835`). A `Removed` reading is disambiguated by a zero-page `COPY|MODE_WP|DONTWAKE` probe: install means truly absent, `EEXIST` means the tracker is stale (`:755-807`). Per-page failure streaks escalate after 8 to avoid a fault/wake livelock (`:47-54`).
- `Prefault` (`prefault.go:23-135`): skip unless `NotPresent`; install as a read (WP-armed) and record `Clean` so the diff inherits it; never retries EAGAIN.

Backend interface (`memory_backend.go:47-68`): `DiffMetadata`, `PrefetchData`, `Prefault`, `Start/Stop/Ready/Exit`, `Memfd` (consumes), `PeekMemfd` (borrows), `ServeStats`. `NoopMemory` is used for cold boots.

### Dirty tracking at pause (`uffd.go:292-381`)
`DiffMetadata` first drains workers (`ExportPageStates`), then either (a) **tracker source** — only legal when the sandbox was resumed with `use_sync_wp` (fail closed otherwise, `:311-318`), or (b) **default: FC's `GET /dirty-memory` pagemap bitmap** (`fc/client.go:617-632`) with the tracker's zero/removed set as `Empty`, and `empty.AndNot(dirty)` so a written zero page stays dirty (`:375`). With sync-WP on, both views are computed and their divergence emitted as `dirty_divergence{tracker_only,pagemap_only}` (`:344-370`) — "burn-in evidence" before trusting the tracker. Note `TrackDirtyPages=false` in the machine config (`fc/client.go:381-386`): they do **not** use FC's own KVM dirty-log Diff snapshots; the pagemap endpoint is their fork's (inferred from the `GetDirtyMemory` operation not existing upstream).

### Memory export at pause (`sandbox.go:2139-2372`, `:2778-2883`; `fc/memory.go:67-173`)
Priority order in `ExportMemory`:
1. In-place checkpoint (`keepMemfdOpen`): copy dirty pages from the **borrowed memfd** without consuming it (`block.NewCacheFromMemfdKeepOpen`).
2. memfd + dedup base: `NewCacheFromMemfdDeduped` — page-granular compare against the parent memfile, dropping pages identical to the parent; budgeted so the diff does not fragment into too many fetch windows (`block/dedup.go:28-46`). Header is built **asynchronously** so Pause returns before the compare (`sandbox.go:2849-2872`); a *provisional* header maps dirty pages to the still-mapped memfd at identity offsets so a same-node resume can start immediately (`metadata.go:100-`, `mapping.go:51-70`, `sandbox.go:2885-2926`), and a pause must parent off the *durable* header, never the provisional one (`:2147-2161`).
3. memfd, no dedup: sync or background copy (`memfd-background-copy` flag, default true).
4. No memfd (old FC): `GET /memory-mappings` → `process_vm_readv` of the FC process's host-virtual ranges (`fc/memory.go:30-65`; `block/cache.go:777-856`, ranges split for `MAX_RW_COUNT`).
The exported diff is packed dirty-page-contiguous (`CoW window sink translates identity offset → rank × pageSize`, `cow_export.go:13-40`). `newBytes = |dirty| × blockSize` feeds `SchedulingMetadata` as a pre-dedup upper bound (`sandbox.go:1968-1978`).

In-place checkpoints always parent on the **original template header**, so exports must be cumulative (`inPlaceExportedDirty`, `sandbox.go:395-404`, `:2233-2250`) — "Chaining diffs on the previous checkpoint's header … is the follow-up." Deferred (CoW-window) memory export, sync-WP tracker dirty source, and memfd handoff are all **fork-gated** (`fcversion/sandbox_features.go:5-19, 32-34, 52-62`).

### Prefetch (`uffd/prefetch/prefetcher.go`, `template/build/phases/optimize/`)
- Build-time: optimize phase resumes the finalized template **twice** (`prefetchIterations = 2`, `optimize/builder.go:33-35`), waits for envd, reads `PrefetchData` (offset, order, access type) from the uffd tracker, and keeps only the **intersection** with averaged order, preferring read (`optimize/prefetch.go:8-56`). Stored in `metadata.json` as `Prefetch.Memory{Indices, AccessTypes, BlockSize}` (`metadata/template_metadata.go:79-86`).
- Pause-time harvest (`server/prefetch_harvest.go:31-110`; flag `pause-resume-prefetch-harvest`): after a pause, do a *throwaway* egress-denied, unregistered resume of the local snapshot, collect its startup fault trace, and rewrite `metadata.json` after the upload lands. Outcomes are metric labels (`success|resume_failed|collect_failed|skipped|persist_deadline`).
- Resume-time: see §2 step 2. `capResumePrefetch` bounds the last-cycle set by `resume-last-cycle-prefetch-max-mib` (`resume_prefetch.go:44-57`).

### Free-page reporting / hinting (fork + guest patches)
`installBalloon(freePageReporting, freePageHinting)` at boot (`fc/process.go:438`); `DrainBalloon` before pause = `start hinting {acknowledge_on_stop}` then poll `host_cmd == FREE_PAGE_HINT_DONE` with 5→50 ms backoff (`fc/process.go:780-830`); FPR is **paused** for the lifetime of a CoW window via `PATCH /balloon/reporting/{pause,resume}` + `GET /balloon/reporting/status` and positively confirmed (`sandbox.go:2184-2231`). All of it needs FC ≥ v1.14 e2b fork (`sandbox_features.go:52-62`). Guest side: `vm.compaction_proactiveness=0` is set in provision.sh because "with 2 MiB host-side hugepage backing … every migration dirties a destination hugepage from the host UFFD's perspective and lands in the next memfile diff" (`base/provision.sh:137-143`).

### Metrics they cut fault latency by
`serveTimer` attrs `[genBucket][pageClass ∈ resident|zero|new][result]` (`userfaultfd.go:579-586`), `wpResolveDuration/Count`, `wpPromoteCount[prevState]`, `prefaultTimer`, plus `uffd.startup.*` at envd-ready (`sandbox.go:3745-3768`); dedup savings `recordSnapshotDedup`; `snapshot.diff.{bytes,ratio}` (`shared/pkg/telemetry/meters.go:374-376`).

## 4. Rootfs / block devices

- **Provider interface** (`orch/pkg/sandbox/rootfs/rootfs.go:29-49`): `Start`, `Close`, `Path`, `ExportDiff` (eject cache + stop VM + copy), `PrepareExportDiff` (eject, return frozen cache for a background seal), `ExportDiffInPlace`, `SwapForBackgroundSeal`, `FoldSealed`.
- **NBD provider** (`rootfs/nbd.go:42-69`): `block.NewCache(size, blockSize, "<sbx>.cow", …)` — a sparse file `Truncate`d to the full rootfs size and mmap'd RDWR (`block/cache.go:62-103`) — layered by `block.Overlay` over the read-only template device (`block/overlay.go:15-41`), exposed through `nbd.NewDirectPathMount`. Overlay `ReadAt` resolves per block: writable cache → sealing (frozen previous) cache → base device (`overlay.go:55-108`). Writes go only to the cache; `WriteZeroesAt` punches holes and marks `Zero` (`cache.go:620-`). Base device block size is the header's (4 KiB for rootfs).
- **NBD server** is in-process: `DirectPathMount.Open` creates `socketpair`s, dispatch goroutines, and `nbdnl.Connect(deviceIndex, socks, size, …, WithBlockSize(4096), WithTimeout(90s))` via netlink (`nbd/path_direct.go:150-260`). Kernel `ioTimeout = 90s` "must be greater than the backend fetch timeout (60s)" (`:35-39`), `deadconnTimeout = 30s`. Device pool requires `modprobe nbd nbds_max=4096` (`nbd/pool.go:76-89`, `start-client.sh:142-143`); host udev rule `nowatch` for `nbd*` disables inotify on the devices (`start-client.sh:133-140`). Dispatch handles READ/WRITE/FLUSH/TRIM/WRITE_ZEROES (`nbd/dispatch.go:67-74, 222-269, 451-471`), 4 MiB request buffers (`:58-64`). `Flush` fsyncs a device fd held open for the whole mount so writeback errors from the guest's lifetime are visible, then `BLKFLSBUF` (`path_direct.go:364-424`).
- **Direct provider** (`rootfs/direct.go:37-`) mmaps a plain file — used for template builds only (`sandbox.go:699-705`), cannot defer exports (`ErrDeferredExportNotSupported`).
- **Rootfs diff at pause** (`sandbox.go:2928-3076`): destroy path = `ExportDiff` ejects the cache, stops the sandbox, waits for the NBD device to be released, then `cache.ExportToDiff(out)` (`rootfs/nbd.go:80-157`): `sync_file_range` as an early-writeback hint, then **`copy_file_range` per dirty range — "On XFS this uses reflink automatically"** — with a plain-copy fallback on `ENOSYS/EXDEV` and short-write handling (`block/cache.go:182-240`). Hence the XFS local disk (`start-client.sh:55-56`). Deferred variant (`defer-rootfs-export` flag) returns the ejected cache and reflinks in the background; in-place variant swaps a fresh `-sealN.cow` cache onto the live overlay and folds it back after sealing (`rootfs/nbd.go:207-253`; `overlay.go:117-164`). The seal filename must keep the `.cow` suffix or startup reclaim's glob misses it (`nbd.go:220-227`).
- **ext4 and page cache** (`sandbox.go:1765-1770`, quoted): "FC never flushes the guest page cache and no memory snapshot will preserve it, so the rootfs must be quiesced before pause or it would persist missing acknowledged writes." Memory snapshots carry the page cache in RAM so they are fine; fs-only snapshots must quiesce: envd native `POST /fsfreeze` (FIFREEZE ioctl, `envd/internal/services/fsfreeze/fsfreeze_linux.go:14-63`, EBUSY/EINVAL idempotent), else `fsfreeze -f` via the exec API behind `fsfreeze-via-exec`, else plain `sync` (`reclaim.go:185-279`). The sync deadline scales with RAM against a 50 MiB/s floor, clamped 5 s–2 min (`reclaim.go:36-52`). Whether it was truly frozen is persisted as `fs_quiesced` (`sandbox.go:1786-1791`).
- **Reboot path** (`reboot.go:76-268`): refuses unless the snapshot is fs-only or the caller demanded a filesystem boot (`:60-62, 92-101`); masks the memfile with an empty one sized to RAM (`:133`), uses **`io_engine = Sync`** "so no async writes are in flight if the sandbox is paused again" (`:146`), replays the build's recorded kernel cmdline verbatim (`:168`), re-sends default user/workdir on `/init` because cold-booted envd has no restored RAM (`:104-115`), and chains pre-boot hooks (`:189-192`): **`e2fsck -p -E journal_only`** on the NBD device inside a systemd-run jail when `fs_quiesced` is false (`:336-433`; `rootfs/fs_recover_linux.go:19-35`) — journal replay only, bounded by journal size, never "condemns" a snapshot because e2fsck exit codes cannot distinguish a bad superblock from a device fault (`:88-97`); and the **offline envd swap** via jailed `debugfs` for quiesced snapshots (`:438-`; `rootfs/envd_swap_linux.go:25-40, 73-87`). Jail posture: `DynamicUser`, empty tmpfs root with `/usr` bind-ro, `PrivateNetwork`, `DeviceAllow=<that one nbd> rw`, `SystemCallFilter=@system-service ~@privileged @resources` (`rootfs/jail_linux.go:21-77`).
- **Template rootfs build** (`template/build/core/rootfs/rootfs.go:118-`): OCI image pulled, extra layers injected (`/etc/hostname`, `/etc/hosts`, `/etc/resolv.conf` naming the tap gateway, `envd.service`, `rcS` busybox init, chrony source script, seed-certs, autologin getty), ext4 extracted; busybox lives at `/usr/bin/busybox` and is the phase-1 init (`:91-98`). `resize disk` grows the quiescent image on the host (`docs/ARCHITECTURE.md:474-478`).

## 5. Templates & builds (`orch/pkg/template/`)

- A template = `{memfile, rootfs.ext4, snapfile, metadata.json}` + headers, keyed by build id (`shared/pkg/storage/paths.go:8-16`). `metadata.json` (`template/metadata/template_metadata.go:105-`): `Version`, `Template{BuildID, KernelVersion, FirecrackerVersion}`, `Context{User, WorkDir, EnvVars}`, `Start{StartCmd, ReadyCmd}`, `FromTemplate`, `Prefetch.Memory`, `CmdlineArgs`, `filesystem_only`, `fs_quiesced`. `SameVersionTemplate` on pause copies kernel/FC versions and **drops** `Prefetch` (memfile-relative) (`server/sandboxes.go:1391-1397`; `sandbox.go:1774-1775`).
- **Why "start from template" is a restore**: the build's last phases run in a real FC VM and end with a pause; the resulting memfile/snapfile *is* the template's memory image. `Server.Create` has no boot branch except `filesystemBoot` (`server/sandboxes.go:289-317`). The `Builder.Build` doc (`template/build/builder.go:116-128`): pull image → inject layers → extract ext4 → **boot with busybox init running only provision.sh, wait for exit** → boot with systemd and wait for envd → run step layers → restart, run configure script + start cmd + ready cmd → snapshot → upload.
- **Phases** (`build/phases/phase.go:31-39`, `Run :61-`): `base → user → steps[] → ensurefreedisk(resize) → finalize → optimize`. Each phase hashes its inputs on top of the source layer hash, checks the layer cache, and either reuses or builds (`runPhase :95-`). Layers are themselves pause-diffs, so a rebuild re-runs only changed steps. Optimize does not create a layer, only metadata (`optimize/builder.go:87-106`).
- **provision.sh** (`build/phases/base/provision.sh`, embedded and templated, 5-minute timeout `provision.go:39-41`): `chattr +i /etc/resolv.conf` (:15), distro detection by `/etc/os-release` ID with a generated selector (:21-37 — "never by probing for a package manager"; distroless rejected by name), install missing packages via the profile's `e2b_pkg_install` (:52-70), ensure the CA bundle (:74-79), `/dev/fuse` 0666 via tmpfiles (:82-84), shell/PS1, remove root password, chrony `makestep 1.0 3` with the refclock chosen at *boot* not build (:105-121 — a PHC line for a missing `/dev/ptp0` "is FATAL to chronyd"), sshd permissive, inotify watches 65536, `vm.compaction_proactiveness=0` (:137-143), `e2b_init_setup` (per-init-system autostarts, OpenRC inittab swap, :147), clear machine-id, **link init into both `/usr/sbin/init` and `/sbin/init` for non-usr-merged Alpine** (:152-158), self-delete and write `0` to the result path (:165-169). Exit status is read back from the console log via prefix `E2B_PROVISIONING_EXIT:` with a 30-line failure tail (`provision.go:111-142`).
- **envd unit** (`core/rootfs/files/envd.service.tpl`): `DefaultDependencies=no`, ordered after journald socket + remount-fs + local-fs + tmpfiles-setup (:6-20, race with `/tmp` wipe documented), `ExecStartPre=/usr/local/bin/e2b-seed-certs` (bind-mounts a tmpfs `/etc/ssl/certs` seeded from a tar packed as the build's last step so `update-ca-certificates` is skipped at boot, :29-49), `Nice=-20`, realtime IO class, `OOMScoreAdjust=-1000`, `Delegate=yes`, `CPUWeight=1000` (:51-60). Enabled by a baked absolute symlink (`core/rootfs/rootfs.go:48-60`, "The target MUST be absolute").
- **Kernel/FC pinning**: every build records `KernelVersion` and `FirecrackerVersion`; resume passes them to `fc.NewProcess` unchanged (`sandbox.go:1257-1268`). FC binaries live at `/fc-versions/<version>/<arch>/firecracker` with a legacy flat fallback (`fc/config.go:48-62`). Version strings: legacy `v1.14.1_431f1fc`, bare `v1.10.1`, or **e2b release `vX.Y-a.b.c`** (`fcversion/version.go:16-25`; `firecracker/fc-versions/README.md:21-28`). Feature gates (`fcversion/sandbox_features.go`): `HasHugePages ≥ 1.7` (upstream), `HasFreePageReporting/Hinting/Memfd ≥ 1.14` (fork line), `HasInPlaceCheckpoint ≥ e2b 0.2.0`, `HasFilesystemSnapshots ≥ e2b 0.1.0` — the last two are "release-based on purpose: legacy and bare dev builds never qualify" (:5-11). Guest kernels are built from `firecracker/fc-kernels/` with a `patches/` dir (FPH needs a virtio_balloon patch per issue #22; not re-verified here).
- **Envd version gating**: `envd/pkg/version.go` (`0.7.0`) must be bumped on behaviour change; the API and orchestrator gate features on the version recorded per build (`docs/ARCHITECTURE.md:221-222`); e.g. kvm-clock ≥ 0.2.11, secure token ≥ 0.2.0 (`api/internal/handlers/sandbox_create.go:51`).
- **Tools**: `cmd/copy-build` copies a build between buckets/local with CRC32C verification (`cmd/copy-build/main.go:28-80`); `cmd/inspect-build` renders headers/mappings/data blocks (`cmd/inspect-build/main.go:20-60`); `cmd/create-build` builds offline; `cmd/resume-build` resumes a build locally with gdb/shell/FPH-bench modes; `cmd/show-build-diff`, `cmd/mount-build-rootfs`, `cmd/hammer-file`, `cmd/simulate-{gcs,nfs}-traffic`.

## 6. Networking (`orch/pkg/sandbox/network/`)

Slot creation, v1 iptables datapath (`network.go:78-360`), executed with the OS thread locked and the host netns restored on exit:
1. If `/var/run/netns/ns-N` already exists it is a stale anchor from a failed teardown → run the full idempotent `RemoveNetwork` first (`:111-121`).
2. `netns.NewNamed("ns-N")` (`:126`); veth pair created *inside* the ns (`veth-N` ↔ `eth0`), `eth0` gets `10.12.x.y/31` (vpeer), `veth-N` moved to the host with the sibling /31 address (`:142-190`).
3. `tap0` in the ns with **fixed host MAC `02:FC:00:00:00:06`** — "Keep resumed guests' cached gateway ARP entries valid. Tap devices are isolated in per-sandbox network namespaces, so sharing this MAC is safe" (`:212-220`); guest side MAC `02:FC:00:00:00:05` (`slot.go:39`). `lo` up, default route via veth (`:236-256`).
4. In-ns NAT: `SNAT 169.254.0.21 → 10.11.0.N` on egress via eth0, `DNAT 10.11.0.N → 169.254.0.21` on ingress (`:265-273`). So the guest is *constant* (`169.254.0.21/30`, gw `.22`) and only the host-side `10.11.0.N` identity varies — exactly pilots' invariant 5.
5. Optional DSCP mangle (scavenger class marker for downstream L3 firewalls, `:276-284`; `pool.go:79-85`), then the per-slot nftables firewall (`:287`).
6. Host side: route `10.11.0.N/32 via 10.12.vpeer dev veth-N` (`:297-303`), FORWARD accepts both ways with the default-gateway iface (`:308-316`), `MASQUERADE` for `10.11.0.N/32` (`:319`), and three `REDIRECT`s on `veth-N` for traffic to the fake orchestrator IP `192.0.2.1` (`pool.go:57`): tcp/80 → hyperloop :5010, tcp/111 → portmapper :5012, tcp/2049 → NFS proxy :5011 (`:323-352`). Finally the egress proxy installs its rules (`:355`).
7. Teardown deletes the namespace **last**, only after every host-side rule succeeded, because the netns entry is the reclaim anchor (`:438-448`).

v2 datapath (`network/v2/`, `NETWORK_VERSION=2`): same netlink setup, in-ns NAT via nftables, host firewall as nftables sets (2 element adds per slot instead of rules), optional eBPF per-veth counters (`v2/network.go:31-40`).

**Slot pool** (`pool.go:217-334`): `NewSlotsPoolSize = 32` pre-created, `ReusedSlotsPoolSize = 100` recycled after `ReturnDelay = 3s` (`:25-31`); `Get` prefers a reused slot, else blocks on a new one, then `configureSlot` re-stamps DSCP and applies the tenant's egress config (`:284-334`). Storage allocates indexes by scanning `/var/run/netns` (`storage_local.go:22-66`), keeping foreign namespaces untouched and reusing leaked ones last.

**Egress filtering**, two layers:
- Per-slot nftables `inet slot-firewall` table, `PREROUTE_FILTER` chain at priority −150 matching `iifname tap0`, with sets `filtered_always_{deny,allow}list` and `filtered_{deny,allow}list` (`firewall.go:47-121`). Rule order: established → predefined allow (control IP + `ALLOW_SANDBOX_INTERNAL_CIDRs`) → user deny → user allow → predefined deny (RFC1918/link-local; TCP-only in BYOP mode) (`:294-334`). `ApplyRules` replaces user sets atomically in one flush (`:368`); `DenyEgress` drops everything but the control path (`:408`).
- **TCP firewall proxy** (`orch/pkg/tcpfirewall/`): when domain rules exist, `nat PREROUTING` REDIRECTs port 80 / 443 / other to three local ports so protocol detection (HTTP Host / TLS SNI via `tcpproxy`) does not block server-first protocols like SSH (`proxy.go:30-70`; `pool.go:71-78`); `isEgressAllowed` matches hostname patterns then CIDRs, and dials the upstream with IP verification against always-denied CIDRs (`handlers.go:53-99, 147-199, 245-265`).
- Bring-your-own egress proxy (`egress_proxy_address`) is flag-gated and needs a build with the dialer (`server/sandboxes.go:191-201`).

**DNS**: `/etc/resolv.conf` is baked at build time with a single `nameserver {{ .Nameserver }}` (`core/rootfs/files/resolv.conf.tpl`) and made immutable during provisioning; the kernel `ip=` line also carries a DNS entry (`fc/process.go:376`). No host-side DNS responder per netns exists (inferred from the absence of any listener on `169.254.0.22:53`) — sandboxes resolve via the host's resolver through NAT.

**Ingress reaches a sandbox** through `10.11.0.N:<port>` from the root namespace; envd's port forwarder runs `socat` from `169.254.0.21:<port>` to `127.0.0.1:<port>` for every LISTEN socket bound to localhost, rescanning every 1 s (`envd/internal/port/forward.go:1-4, 26`; `envd/main.go:41, 326-341`).

**Guest→host services**: hyperloop `:5010` (Gin, `/logs` + `/me`, `orch/pkg/hyperloopserver/server.go:26-`), NFS proxy `:5011` + portmapper `:5012` for persistent volumes (`orch/pkg/nfsproxy`, `pkg/portmap`; envd mounts them from `/init`'s `VolumeMounts`, `envd/internal/api/init.go:303-304`), MMDS at `169.254.169.254` (`host/mmds.go:21`).

- **Identity**: polls MMDS (`PUT /latest/api/token` then GET) for `{instanceID, envID, address, accessTokenHash}` (`host/mmds.go:18-40, 56-`), which the orchestrator writes via `PUT /mmds` after resume or before a cold boot (`fc/process.go:462, 641`). Writes `.E2B_SANDBOX` into `/run/e2b` and sets `E2B_SANDBOX=true` env (`main.go:181-190`).
- **`POST /init`** (`internal/api/init.go:138-`, body `SetData :257-310`): validates the access token against the MMDS hash (self-authenticating; `/init` is otherwise auth-exempt, `auth.go:24-30`), then: set system time from the request timestamp if drifted (clock re-sync after pause — `clock_linux.go`), replace user env vars, take the access token, start hyperloop setup, default user/workdir, install the egress-proxy CA bundle, mount NFS volumes; thaws user cgroups frozen before pause (`:218-220`); replies `204` with `X-Envd-Version`, `X-Envd-Freeze-Audit`, `X-Envd-Handover` headers (`:141-155`, read at `orch/pkg/sandbox/envd.go:515-535`). Stale/replayed inits are ignored by timestamp (`:230`). Serialized by `initLock` (`:190`).
- **Control routes** marked `x-internal` in the spec: `/collapse /freeze /fsfreeze /fsthaw /init /unfreeze` + `/upgrade` (`orch/pkg/sandbox/envd/internal_routes.gen.go:8-15`, `internal_routes.go:14-16`); the orchestrator proxy refuses them for any method, decoded-path-cleaned (`internal_routes.go:34-63`; `orch/pkg/proxy/proxy.go:77-90`).
- **Public API**: REST `/health`, `/metrics`, `/envs`, `/files` (upload/download, signed URLs), `/files/compose` (`spec/envd.yaml:17-313`); Connect `Process{List, Connect(stream), Start(stream), Update, StreamInput(stream), SendInput, SendSignal, CloseStdin}` (`spec/process/process.proto:5-20`); `Filesystem{Stat, MakeDir, Move, ListDir, Remove, WatchDir(stream), CreateWatcher, GetWatcherEvents, RemoveWatcher}` (`spec/filesystem/filesystem.proto:7-19`). Process start runs as the authenticated user via `syscall.Credential` (`services/process/handler/handler.go:224`), optional PTY via `creack/pty` (`:294-302`), per-request timeout header, keepalive events on the stream (`services/process/start.go:24-120`), processes placed in per-type cgroups (`services/cgroups/`).
- **Auth** (`internal/api/auth.go:24-70`): `X-Access-Token` compared constant-time; `/health`, `/files` (signed), `/init` exempt; a live-upgraded envd fails **closed** before its post-upgrade `/init` restores the token (`:40-43`, `:60-70`).
- **Pre-pause hooks**: `/freeze` + `/unfreeze` freeze user cgroups (`services/cgroups/freeze.go`; orchestrator `reclaim.go:88-100`, flag `freeze-user-cgroup`), `/collapse` compacts envd's own heap (flag), `/fsfreeze`/`/fsthaw` (§4). A thaw watchdog thaws anyway if `/init` never arrives (`main.go:245-256`).
- **Live upgrade** `POST /upgrade`: stream the new binary, `syscall.Exec` into it with the same PID carrying stdio/PTY fds and process table via a tmpfs handover blob (`services/process/upgrade.go`; `docs/ARCHITECTURE.md:213-219`).
- **Logs**: an HTTP exporter posts guest logs to the MMDS-provided `address` (hyperloop) (`main.go:203-208`).

What pilots' guest agent should take: MMDS-delivered identity + token hash so the agent self-authenticates `/init`; an `/init` that is the *only* channel for env/user/workdir/token after every resume (and re-syncs the clock); control routes on the same port but refused at the proxy by path, method-agnostic; fsfreeze/thaw and cgroup-freeze endpoints; localhost port scanning + forwarding so `127.0.0.1` binds are reachable; version header on `/init` to gate features; keepalive frames on exec streams.

## 8. client-proxy / ingress

- **URL encoding**: `https://<port>-<sandboxID>.<domain>`; `parseHost` keeps the left-most label, splits on the first `-`, port first (`shared/pkg/proxy/host.go:75-97`). Alternative: header routing `E2b-Sandbox-Id` / `E2b-Sandbox-Port` when the host is `localhost`, an IP, or `sandbox.<domain>` (`:16-43, 108-111`).
- **TLS** terminates at the cloud LB / Traefik (`docs/ARCHITECTURE.md:487`; `iac/modules/job-ingress`), not in client-proxy (plain HTTP :3002 with h2c, `shared/pkg/proxy/proxy.go:46-73`).
- **Routing**: `catalogResolution` = Redis `GetSandbox(id)` → `OrchestratorIP`; on `ErrSandboxNotFound` → `handlePausedSandbox` → API gRPC `ResumeSandbox(id, port, trafficToken, envdToken)`; NotFound → not allowed, PermissionDenied, ResourceExhausted, FailedPrecondition "still transitioning" mapped to typed proxy errors (`client-proxy/internal/proxy/proxy.go:75-137`). Target is always `http://<nodeIP>:5007` (`:30, 196-199`). **Wake-on-request exists, but is L7-only and API-mediated**; the connection is held while the API waits out a pause transition (up to 3 retries within a budget, `api/internal/orchestrator/autoresume.go:20-85`). fs-only snapshots are explicitly *not* auto-resumable ("traffic always memory-resumes", `docs/ARCHITECTURE.md:413-414`; `api/internal/handlers/sandbox_create.go:184-186`).
- **Connection pooling**: one `pool.ProxyPool` keyed by `ConnectionKey` — a constant key for client-proxy → nodes, the sandbox `LifecycleID` for node-proxy → guest so a recycled slot IP never reuses a stale connection (`orch/pkg/proxy/proxy.go:141-143`); `maxClientConns = 16384` (`shared/pkg/proxy/proxy.go:28`); client-proxy retries once, node proxy 5× "to handle port forwarding delays in sandbox envd" (`:41-44`; `orch/pkg/proxy/proxy.go:168-170`); node proxy disables keep-alives to the guest (`:171-174`).
- **Node proxy** (`orch/pkg/proxy/proxy.go:66-155`): resolves the sandbox from the in-memory map, refuses envd control paths, enforces `e2b-traffic-access-token` for non-envd ports (constant-time; preflights fail too by design), optional host masking, HTTPS to guest ports listed in `ingress.https_ports` with `InsecureSkipTLSVerify` (self-signed guest certs), per-sandbox connection limiter from flag `SandboxMaxIncomingConnections`. Removed from the pool on sandbox stop (`server/sandboxes.go:1573-1576`).
- Websocket/streaming: handled by the generic reverse proxy (`shared/pkg/proxy/handler.go`, `stream_abort.go`); not re-verified in detail.

## 9. Persistence, auto-pause, multi-host

- **Is a paused sandbox resumable on another host?** Yes, by construction: pause writes a new build `{memfile diff, rootfs diff, snapfile, metadata.json, headers}` to object storage asynchronously (`server/sandboxes.go:1498-1540`, retry budget in `upload_retry.go`) and any node's `templateCache.GetTemplate(buildID, isSnapshot=true)` resolves the chain through headers (`template/storage_template.go`). Placement merely *prefers* the origin node for cache warmth (`docs/ARCHITECTURE.md:405-407`); if the origin has the snapshot locally, resume reads nothing remote. The API answers `FailedPrecondition` until the upload lands (`server/sandboxes.go:320-325`). Origin is remapped to the "warmest" node after a placement timeout (`create_instance.go:530-560`).
- **Local cache tiers** on a node: `/orchestrator/build` diff store (TTL 25 h, `template/cache.go:33-39`), template cache (25 h TTL, evicts + purges peers), optional shared NFS chunk cache (`shared/pkg/storage/storage_cache.go:54-75`, flags `use-nfs-for-{snapshots,templates}`), and **P2P chunk serving** (`ChunkService`, `template/peerserver`, `peerclient`, flag `peer-to-peer-chunk-transfer`): a node can serve a just-paused build's chunks to a peer *before* the upload completes (`peer-to-peer-async-checkpoint`), with `IncompletePendingUpload` headers flagged so they are never persisted (`header/serialization_v4.go:32-36`). Node-local disks are XFS on local NVMe (RAID0 if several), plus a 100 GiB swapfile with `vm.swappiness=10` (`start-client.sh:19-84`).
- **CPU compatibility**: snapshot rows pin the source build's CPU info; placement filters nodes by CPU/feature compatibility (`placement/cpu_compatibility.go`, `feature_compatibility.go`; `pause_instance.go:42-55` logs origin CPU model/flags "for debugging cross-generation pools"); fs-only resumes can be pinned to a CPU model by flag (`create_instance.go:587-606`). Same vendor-lock reality as pilots' rule 6.
- **Snapshot chains**: every pause parents on the resumed build (`Generation+1`); in-place checkpoints parent on the original template with cumulative exports (§3). `SchedulingMetadata` lists ≤128 build ids per artifact with bytes so a scheduler could prefer nodes holding the chain (`scheduling/metadata.go:14-49`) — the API has the data but placement scores CPU only (inferred from `Score`).
- **Timeouts/auto-pause**: API-side evictor (§central list); `autoPause` default from `sandbox.AutoPauseDefault`, `autoPauseMemory=false` selects fs-only snapshots (`handlers/sandbox_create.go:151-186`); `autoResume{policy, timeout}` stored with the sandbox and forwarded to the orchestrator config (`create_instance.go:319-350`). `Checkpoint` RPC = pause + resume-in-place (fork-gated) or pause + fresh resume (`server/sandboxes.go:937-1319`).
- **Node draining**: `ServiceInfo` status `Healthy|Draining|Unhealthy|Standby` reported over `InfoService` (`orch/pkg/service/info.go:19-37`); Draining cannot be overridden back to Standby (`:52-63`); graceful `Close` waits for in-flight uploads and polls the live sandbox count with backed-off logging (`server/main.go:36-58`). Sandboxes are **not migrated** on drain — they run out or are paused by the API (inferred: no migration RPC exists).
- **Orchestrator crash**: startup reclaim kills orphaned FC processes and netns (§2). Running sandboxes die; the API's `Store.Reconcile` reconciles its Redis view against `List` from each node (`api/internal/sandbox/store.go:140`), and an orphan reconciler kills VMs the API no longer knows about ~20 s later (`server/sandboxes.go:849-856` comment).
- **Volumes**: persistent volumes are host directories exposed to guests over NFS through the per-slot proxy (`orch/pkg/volumes`, `nfsproxy`, `chrooted` for path confinement), managed via `VolumeService` gRPC and content served by a separate "belt" service (`docs/ARCHITECTURE.md:354-389`). Placement can require volume labels (`sandbox-volume-label-based-scheduling`).

## 12. Multi-tenancy / security

- **No jailer.** FC is exec'd directly as root from the orchestrator via `unshare -m` + `ip netns exec` (`fc/script_builder.go:54-63`; `fc/process.go:206`). Isolation relies on KVM, the per-slot netns, and cgroups; no seccomp on FC (inferred from the start script — no `--seccomp-level`), no uid drop, no chroot. The Nomad job runs the orchestrator itself as root via `raw_exec` (`orchestrator.hcl:55`; `docs/ARCHITECTURE.md:514-515`).
- **cgroups v2**: `/sys/fs/cgroup/e2b/<sandbox>` created per sandbox, FC placed atomically with `CLONE_INTO_CGROUP`, stats read from `cpu.stat` + `memory.peak` (per-fd reset), removed on close; failure degrades to "no accounting" rather than aborting (`cgroup/manager.go:24-60`; `sandbox.go:3633-3651`). Guest-side cgroups are managed by envd (`Delegate=yes`).
- **Network isolation**: per-slot nftables deny of private ranges + optional domain allow/deny via the TCP firewall; control IP `192.0.2.1` is the only host address a guest can reach; ingress only through the node proxy with a per-sandbox traffic token (§6, §8).
- **Rate limits**: FC token buckets for net tx and rootfs drive, flag-driven, re-applied on every resume (`fc/process.go:130-146, 604-620`); per-sandbox inbound connection cap (`SandboxMaxIncomingConnections`); egress DSCP marking for scavenger-class shaping.
- **Host-side tools that parse tenant bytes** (e2fsck, debugfs) run in a hardened `systemd-run` jail (§4). `chrooted` confines volume file ops (`orch/pkg/chrooted`).
- **Guest identity/secrets**: envd access token delivered as a *hash* via MMDS and the plaintext via `/init` over the host-only slot network; secrets store markers resolved at egress in the EE build (`docs/ARCHITECTURE.md:124-134`); workload-identity token definitions passed through `SandboxConfig.iam` (`:109-116`).
- **Quotas** are enforced in the API (team limits, `MaxLengthHours`, concurrent sandboxes), not on the node; the node only caps *starting* sandboxes and NBD/net slots.

## Lessons pilots should COPY (mechanics only)

1. **Zero-fill via `UFFDIO_COPY` of a static zero buffer with `MODE_WP`, not ZEROPAGE→WRITEPROTECT** (`userfaultfd.go:967-976`) — required for 2 MiB pages and closes two lost-write windows. → `apps/hostd/internal/uffd/handler.go` (issue #22 lever 1).
2. **Uniform page size per VM, refuse mixed regions; read `page_size_kib` as bytes** (`userfaultfd.go:235-243`, `region.go:12-13`). → `internal/uffd` (already partially there per #22; extend to accept uniform-2M).
3. **Deferred-fault queue + self-wake pipe for EAGAIN / short hugetlb copies** (`userfaultfd.go:136-139, 1070-1079`; `fd.go:150-166`) — the kernel never redelivers. → `internal/uffd`.
4. **Separate worker pools for MISSING vs WP faults** and the `settleRequests`/`readSerial` lock split so a REMOVE batch cannot deadlock behind a slow source read (`userfaultfd.go:107-134`). → `internal/uffd` (only if pilots adds WP/REMOVE handling).
5. **Page-state lattice with `Clean` excluded from the diff** (`tracker.go:11-38`) so prefaulted-but-unwritten pages inherit from the parent instead of bloating the next diff. → `internal/uffd` + `internal/block` diff builder.
6. **Last-cycle prefetch from the diff header, fetch-only** (`resume_prefetch.go:61-144`; `sandbox.go:1054-1146`). → `internal/uffd/control.go` replay (#22 lever 3).
7. **Build-time prefetch trace = intersection of 2 resumes**, stored in metadata (`optimize/prefetch.go`). → `internal/build`/`internal/machines/template.go`.
8. **`rootflags=discard` + per-pause `fstrim → sync → drop_caches → compact_memory` chain, `vm.compaction_proactiveness=0` in the guest** (`fc/process.go:81-86`; `reclaim.go:56-84`; `provision.sh:137-143`). → guest agent + template build (#22 lever 4).
9. **fs-only snapshots need FIFREEZE in the guest and `fs_quiesced` persisted; cold boots of non-quiesced rootfs get `e2fsck -p -E journal_only` in a jail first** (`sandbox.go:1765-1791`; `reboot.go:336-433`). → `internal/machines`, guest agent (#22 lever 5).
10. **Cold boot of a snapshot uses `io_engine=Sync`** so a re-pause has no async writes in flight (`reboot.go:146`). → `internal/fc/boot.go`.
11. **`copy_file_range` for the rootfs diff (reflink on XFS), with fallback + short-write loop** (`cache.go:207-240`). → `internal/block/chunkify.go` / pause path — pilots' reflink requirement, same idea.
12. **Overlay with a swappable "sealing" cache** so an in-place checkpoint's reflink runs off the critical path and folds back (`overlay.go:117-164`; `nbd.go:207-253`). → `internal/nbd` handler.
13. **NBD kernel timeout > backend fetch timeout; `nowatch` udev rule; device fd held open for writeback-error visibility; `BLKFLSBUF` on flush** (`path_direct.go:35-43, 364-424`; `start-client.sh:133-140`). → `internal/nbd/process.go`, `scripts/host-bootstrap.sh`.
14. **Constant guest addressing with in-ns SNAT/DNAT, fixed gateway MAC so resumed guests' ARP stays valid, netns entry as the reclaim anchor deleted last** (`network.go:212-273, 438-448`). pilots already has invariant 5; copy the MAC pinning and the anchor-last teardown. → `internal/netns/setup.go`.
15. **Pre-created slot pool + 3 s return delay before reuse; proxy connection pool keyed by a per-boot lifecycle id** (`pool.go:25-31`; `proxy.go:141-143`). → `internal/netns`, `internal/router`.
16. **Control routes on the agent port refused at the proxy by cleaned decoded path, method-agnostic; `/init` self-authenticates via an MMDS-delivered token hash** (`internal_routes.go:34-63`; `envd/internal/api/auth.go`). → `internal/router`, `cmd/guest-agent`.

## What pilots should REJECT and why

- **Central API / Redis catalog / Postgres snapshot rows / Nomad discovery / API-side evictor / LaunchDarkly** — all violate rule 1. pilots' Corrosion row + local subscription cache is the replacement; timeouts belong on the owning host.
- **Forked Firecracker features**: sync-WP userfault delivery + tracker dirty source, CoW-window deferred memory export, memfd handoff on snapshot load, `/dirty-memory` pagemap RPC, `/memory-mappings`, balloon FPR/FPH endpoints and pause/resume of reporting, in-place checkpoint (pause+snapshot+resume of the same process is upstream-possible, but their CoW export is not) — gated by `fcversion/sandbox_features.go`, `fph_gates.go`. Upstream `Diff` snapshots + `track_dirty_pages` give pilots O(dirty) pause without the fork (#22 lever 2). Note e2b sets `TrackDirtyPages=false` and `SnapshotType=Full` (`fc/client.go:144, 381-386`) — do not copy that pairing; it only makes sense with their pagemap RPC.
- **Patched guest kernels** (`firecracker/fc-kernels/patches/`) — same maintenance bill.
- **No jailer, FC as root** (`script_builder.go`) — pilots' multi-tenant row requires jailer + seccomp; e2b's posture is weaker here.
- **L7-only, API-mediated wake-on-request** (`client-proxy/internal/proxy/proxy.go:97-137`) — pilots' L3 wake is the deliberate differentiator (#14).
- **Kill-on-orchestrator-restart with no re-adoption** (`startupreclaim/`) — pilots' hostd restart should re-adopt running FC processes or at least suspend-then-restore; "wipe any host's disk; nothing is lost" is stronger than e2b's model.
- **NFS shared chunk cache and P2P chunk serving** — engineering for GCS latency at their scale; pilots' Hetzner Object Storage in-region + local NVMe cache is enough for the crisp gate. Revisit only if cold resume misses the SLO.
- **Redis-TTL routing entries and `MaxLengthInHours`-bounded catalog** — pilots' URLs are permanent; nothing may expire a route.
- **Per-sandbox `socat` port forwarding of localhost binds** (`envd/internal/port/forward.go`) — a pragmatic hack; pilots can do the same but should prefer telling users to bind `0.0.0.0` or use an eBPF/iptables REDIRECT inside the guest. (inferred preference)
- **In-ns iptables v1 datapath** — e2b is itself moving to nftables sets (`network/v2/`); pilots already uses nftables (`internal/netns/firewall.go`).

## Open questions

1. Does upstream FC's `Diff` snapshot + `track_dirty_pages` interact correctly with a uffd-backed memory region (KVM dirty log is on the host VMA regardless of backing)? e2b never uses this path, so their code is no evidence either way — must be measured (#22 gate 2).
2. e2b's hugepage path relies on `UFFD_FEATURE_MISSING_HUGETLBFS` and FC ≥ 1.7 upstream; does pilots' current kernel on the Hetzner image expose `WP_ASYNC`/hugetlb WP (needed only if pilots ever adopts read-install-with-WP)? Not required for lever 1.
3. The `page_size_kib`-in-bytes quirk is tied to "the deprecated version" of the mapping format (`region.go:12-13`); which upstream FC version switched to `page_size`? Check against the FC version pilots pins before parsing.
4. e2b's memfile dedup budget (`block/dedup.go:28-46`) is tuned against 2 MiB compression frames; pilots' content-addressed chunk size should be checked against fault granularity so a 2 MiB hugepage fault never spans two remote fetches.
5. Does the guest kernel pilots ships honour `rootflags=discard` TRIM through virtio-blk so the NBD `WriteZeroes/Trim` path (`dispatch.go:451-471`) actually shrinks diffs? Requires `discard` support end-to-end; verify with `fstrim -v`.
6. Whether e2b's `optimize` two-run intersection is worth it for pilots' create-from-template SLO, or whether replaying the *previous* diff (lever 3) alone gets there — measurable with the existing battery.
7. e2b's fs-only snapshots are not auto-resumable by traffic; pilots' `autoStop: stop` machines wake via boot on request — the same crash-consistency caveats apply (FIFREEZE before stop), and pilots' boot-on-wake latency should be compared against e2b's `rebootEnvdTimeout = 60s` ceiling (`reboot.go:43`).
